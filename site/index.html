MainsMarker

An AI agent that reviews UPSC Mains answers and can prove what it did. Its identity is an ARC-69 Agent ID asset that pins its Agent Card, other agents pay it per review over x402 on Algorand (fees paid by the facilitator through fee pooling), and every review leaves an ARC-2 audit note on-chain with the model and rubric used.

1 · Ask for a review

The button calls StudyBuddy, a separate buyer agent (own service on another cloud, own key). It fetches this agent's card over HTTP, checks the Agent ID on-chain, applies its spending policy, then pays over x402. TestNet only; no real money moves.

          How it works

          Verified identityMainsMarker's Agent ID is ARC-69 asset #775327772, created by its payment account. Its metadata pins the SHA-256 of the Agent Card, so a buyer can check it is paying the agent the card describes.
          Pay per call (x402)POST /x402/review answers 402 with an exact-scheme price in an ASA. A signed atomic group in PAYMENT-SIGNATURE unlocks it.
          GaslessThe facilitator verifies and simulates the group, adds its fee-payer transaction and pays all fees (fee pooling), so buyer agents hold only what they spend.
          AccountabilityEach review is anchored as an ARC-2 note (mainsmarker:j…): input hash, review hash, rubric version, model, payment, score.

          Verify any review

          Paste a review JSON (the review object an agent received) and its audit transaction id. Your browser hashes the canonical JSON (keys sorted, no spaces) and compares it with the hash anchored on Algorand. Every check reads the chain directly from your browser (the public AlgoNode TestNet indexer); MainsMarker's own API is not asked, so the seller cannot vouch for itself.

          Trust model (what you have to trust, and what you don't)

          • You don't have to trust MainsMarker about what it said. Every review's hash, its input hash, the rubric hash, the model and the payment are in an ARC-2 note on-chain, and StudyBuddy writes its own receipt with the hash it received. The verifier above reads both from the public indexer in your browser.
          • You do have to trust MainsMarker to refund. The refund is a transfer the seller sends when a paid review fails; it is visible on-chain, but nothing forces it. The x402 exact scheme pays the seller directly, so an escrow would need a different scheme. An escrow app (pay → claim with the review hash, or refund after N rounds) is the next step, not shipped.
          • The facilitator is ours. It runs in the same deployment as the seller and pays the network fees (fee pooling) from its own account, LYWBPK4O…; it verifies and simulates the group before submitting, so it cannot change the amount or payee the buyer signed.
          • The buyer protects itself. StudyBuddy refuses to pay unless the Agent ID asset was created by the payee and pins the card it fetched, and it enforces a price cap and a daily budget computed from its own on-chain history (not from memory).
          • Seller-side rate limits live in function memory and reset when the function restarts; they are abuse protection, not accounting.

          For agent builders

          Any x402 client with an AVM signer can buy a review directly (the 60-line scripts/buy.mjs in the repo does it).

          curl -i -X POST https://mainsmarker-algo.vercel.app/x402/review -H 'content-type: application/json' \
  -d '{"question":"…","answer":"…","marks":10}'
# → 402 + PAYMENT-REQUIRED (scheme exact, network algorand:SGO1GKSz…, asset 775327739, 250000, feePayer)
# retry with PAYMENT-SIGNATURE: base64(x402 payload with the signed group) — see scripts/buy.mjs
